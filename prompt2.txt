## High-Level Vision (CRITICAL CONTEXT)
This application is a **policy-driven machining decision engine** (not “just a calculator”). It must:
1) Produce deterministic feeds & speeds recommendations plus warnings and confidence
2) Make trade-offs explicit and explainable
3) Support optimization intents (tool-life, balanced, time) as **policy profiles**
4) Support multiple policies at once, detect conflicts, and resolve deterministically via arbitration
5) Import Fusion 360 tool library JSON to validate tool geometry and export back a Fusion-compatible profile + presets
6) Treat “explainability” as a first-class output artifact (like an audit log / policy decision trace)

Primary users:
- Self-taught hobbyist machinists
- Students
- Experienced machinists who want a sanity-check tool

Secondary goal:
- Be a portfolio-quality platform/DevOps artifact (schemas, policy engine, CI tests, infra, monitoring, security scanning)

## Backend Requirements (FastAPI)

### Backend Core Principles
- Deterministic computation (no AI/ML in MVP)
- Clear schema contracts (Pydantic v2)
- Separation of concerns:
  - engine/ contains pure domain logic (no I/O)
  - api/ contains routing, auth, request validation
  - db/ contains persistence mappings
- Unit-consistent: store and compute in **mm** internally; UI supports inch/mm conversions

### Core Schemas (Pydantic) — MUST IMPLEMENT
In backend/engine/schemas/: Tool, Material, Machine, Workholding, Coolant, Operation, Policy, Signals, Recommendation.

### Domain Engine (backend/engine/) — MUST IMPLEMENT
Pipeline:
1) Normalize inputs
2) Compute baseline feasible ranges (material + tool + machine)
3) Compute derived signals (risk scores)
4) Apply policies (safety first, then optimization)
5) Detect conflicts
6) Arbitrate deterministically via weighted strategy
7) Emit recommendation + explanation trace

### Fusion Tool Import/Export (MVP)
- Import Fusion 360 tool JSON
- Validate geometry relationships (blocking and warning rules)
- Export Fusion-compatible JSON with presets for variants
